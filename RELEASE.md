# Station Control — релиз для домашнего использования

**Station Control** (YNDX-0008) — локальная панель и AirPlay для Яндекс
Станции Макс. Это форк Windows-дашборда **Station Control 0.4.4**: оригинал
работал на компьютере и подключался к станции по ADB/SSH, а эта версия
работает на самой станции, без ПК.

Состояние на 11.11.2026. Станция: Яндекс Станция Макс, Android 9,
прошивка `PPR1.180610.011.5000000921`. Всё ниже проверено на этой станции.

Статус: **готово для личного/домашнего использования**. Для публичного
релиза остаются принципиальные ограничения (см. «Ограничения»).

## Сборка

Сборка из исходников нужна разработчикам. Готовые APK и бинарник панели
прикладываются к GitHub Release (см. «Публикация» ниже).

```powershell
.\build-all.ps1                 # панель + видео APK + ТВ APK + checksums -> dist\
.\build-all.ps1 -SkipVideo      # быстрая сборка одной панели
```

`dist\` содержит артефакты, `SHA256SUMS.txt` и `BUILD.txt`.
Предыдущий набор при сборке переезжает в `dist\previous\` — это источник
для отката панели.

## Публикация

В репозиторий попадают только исходники, скрипты и гайд. Готовые артефакты
(`station-web`, `airplay-video-*.apk`, `airplaytv-*.apk`,
`shairport-*.apk`, `wifi.dex`, `SHA256SUMS.txt`) прикладываются к GitHub
Release. Служебный скрипт синхронизации с GitHub остаётся локально и в
публичный снимок не входит. В снимке нет приватного host-ключа,
debug-дампов и APK видео-приёмника. Rollback-APK в репозиторий не входит:
скачайте `airplay-receiver-upstream.apk` из Release и положите в `dist\`
или передайте `rollback.ps1 -Apk <путь>`.

## Установка и обновление

```powershell
.\deploy.ps1            # панель + скрипты, затем перезапуск
```

`deploy.ps1` копирует бинарник и скрипты через ADB, выполняет
`/data/local/tmp/station-web/install.sh` по SSH и проверяет версию через API.
Логин по умолчанию — `admin` (как в шаблоне `stage/station-web.conf`). Если
вы переименовали пользователя, передайте `-User` или `STATION_USER`.
Пароль передаётся параметром `-Password` или переменной окружения
`STATION_PASSWORD`; без пароля деплой выполняется, но проверка версии
пропускается. IP станции задаётся через `-HostName`/`-Device` или
`STATION_HOST`; пример — `192.168.1.100`. SSH-ключ по умолчанию
`stage\ssh\client_ed25519` (в репозиторий не входит); если он в другом
месте — передайте `-Key`. `adb` берётся из `platform-tools\` или из `PATH`.

Wi-Fi-хелпер (`wifi.dex`) собирается отдельно:
`powershell -File stage\wifi\build.ps1`. `deploy.ps1` кладёт его в
`/data/local/tmp/station-web/wifi.dex`; без него панель откатывается на
старый путь через wpa_supplicant.

Все `.ps1` в репозитории сохранены как UTF-8 с BOM: PowerShell 5.1 иначе
читает кириллицу как ANSI и ломает разбор скрипта.

Видео-приёмник:

```powershell
powershell -File stage\airplay_video\install.ps1
```

Имя видео-приёмника после переустановки применяет `/odm/bin/apply-video-name.sh`
из настройки `station_airplay_video_name`; `install.ps1` вызывает его
локально на станции, поэтому UTF-8 не проходит через консоль. Скрипт также
ждёт, пока приёмник откроет `7001`, и повторяет запуск, если первый пуск
после переустановки остался пустым процессом.

## Откат

```powershell
.\rollback.ps1 -Target video   # официальный APK приёмника
.\rollback.ps1 -Target panel   # предыдущая панель из dist\previous
```

ТВ-приложение с понижением версии ставится только через
`adb uninstall com.opencode.airplaytv` + `adb install`.

## Аудит и сторож

```powershell
ssh -p 2222 -i <ваш-ключ> root@<IP> sh /odm/bin/station-audit.sh
```

Аудит печатает прошивку, версии, порты, состояние сервисов, настройки имени
и темы, состояние hosts-bind и хвост журнала сторожа. Это первый шаг после
любого OTA или сброса.

`station-guard.sh` поднимается init-сервисом `stationguard` после загрузки и
раз в 20 с проверяет: жива ли панель (перезапуск не чаще раза в 60 с), живы ли
Shairport и видео-приёмник (не чаще раза в 2 мин). Журнал:
`/data/local/tmp/station-guard.log` (ротация 256 КБ).

## Проверка после установки

1. `http://<IP>:8080` — панель открывается, версия совпадает.
2. AirPlay-аудио: станция видна в списке AirPlay, играет, пауза/возврат.
3. AirPlay-видео: незащищённый HLS играет; на DRM-потоке появляется
   спокойная карточка «Защищённый фильм», а не чёрный экран.
4. Матрица → вкладка «Анимации»: карточки проигрывают родные GIF станции,
   «Глаза» и «Сердце» проверяются в первую очередь.
5. Имя: кнопка «Имя» рядом с переключателем AirPlay. Режим «Умный дом»
   подставляет имя и комнату без бренда «Яндекс» (`Станция Макс (Спальня)`),
   «своё» — произвольное до 30 символов. Видео-приёмник получает то же имя
   с суффиксом «· Видео».
6. Перезагрузка: панель на 8080 сразу, оба приёмника — в пределах ~45 с,
   имя и тема сохраняются.

## Ограничения

- **FairPlay/DRM не играет через AirPlay.** Кинопоиск и другие защищённые
  сервисы смотрятся нативным приложением на станции. Приёмник определяет
  DRM в манифесте и показывает спокойную карточку на русском («Защищённый
  фильм»), а не красную ошибку и не чёрный экран.
- **Bluetooth-наушники не поддерживаются.** В прошивке включён только
  A2DP Sink: `A2DP Source State: Disabled`, профиля `A2dpSourceService` нет.
  Софтово не включается; вариант — внешний BT-передатчик на линейный выход.
- Приёмники поднимаются после ребута не мгновенно (~45 с) — это штатный
  старт вендорных приложений.
- Имя в списке AirPlay укладывается в строку: бренд «Яндекс» убирается,
  комната добавляется только если всё помещается, лимит 30 символов.
  Видео-приёмник получает короткое имя без комнаты —
  `Станция Макс · Видео`, чтобы отличаться от аудио и не обрезаться.
- Имя видео-приёмника меняется при сохранении имени в панели и при старте
  панели (перезапуск сервера на любое изменение `server_name` рвёт
  соединения, поэтому периодической переотправки нет).
- Комната берётся из Умного дома. Если она не назначена, будет только имя.

## Безопасность

- Пароль панели хранится как PBKDF2-SHA256 (120 000 итераций), открытый
  текст в `/odm/etc/station-web.conf` не пишется. Старый конфиг мигрирует
  автоматически при первом запуске.
- Перебор: 5 неудачных попыток → блокировка IP на 5 минут.
- POST-запросы проверяют `Origin`/`Referer`; ответы получают
  `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`.
- Сессии, токен Glagol и журнал событий лежат в
  `/data/local/tmp/station-web/private` (0700, файлы 0600).
- Панель предупреждает в настройках, только пока действует стандартный
  `admin/admin`. Смените пароль в разделе «Настройки → Доступ к панели».
- SSH (2222) — канал обслуживания станции. ADB (5555) можно выключить
  тумблером в разделе «Доступ»: состояние хранится в настройке
  `station_adb_enabled`, переживает перезагрузку, и `adbguard` больше не
  поднимает ADB сам. Включить обратно — тем же тумблером или по SSH:
  `settings put global station_adb_enabled 1` и
  `settings put global adb_enabled 1`.
- `deploy.ps1` обновляет панель через ADB. Если ADB выключен, сначала
  включите его в панели или по SSH. После включения скрипт сам выполняет
  `adb connect` (клиент не находит TCP-устройство автоматически).

## После OTA прошивки

1. `sh /odm/bin/station-audit.sh` — сравнить с этим файлом.
2. Если `/odm` перетёрт: заново выполнить `deploy.ps1` (вернёт панель,
   guard, audit, init-сервисы) и `stage\airplay_video\install.ps1`.
3. Проверить hosts-bind (`hosts_bind: yes`) и что апдейтер отсутствует.
4. Проверить, что `stationguard` = `running` (появится после ребута).
