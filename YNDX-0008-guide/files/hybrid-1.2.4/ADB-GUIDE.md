
# ADB на Яндекс Станции Макс YNDX-0008

Инструкция подходит для передачи человеку или агенту: настройку DNS и Nginx нужно адаптировать к конкретной сети.

Способ проверен на **подписочной** Станции Макс YNDX-0008 (`yandexstation_2`, Android 9, прошивка `5000000921`). На обычной модели его тоже можно попробовать, но отдельно он не проверен. На других моделях и прошивках результат не подтверждён.

Для получения обычного ADB-shell root не нужен. DNS и сервер подмены должны оставаться доступными после настройки.

> **Если станция подписочная:** значение `transaction` в ответе ниже меняет состояние, которое видит станция. Оно не оплачивает и не отвязывает подписку на устройство и не выдаёт Яндекс Плюс. Доступ к платным сервисам зависит от прав аккаунта. По исходному описанию проверки при действующем Плюсе работали Алиса, музыка и Кинопоиск. Перед проверкой был выполнен сброс станции; необходимость сброса не проверялась.

## Что понадобится

- Станция и компьютер в одной локальной сети; адрес станции должен быть известен.
- DNS-сервер и Nginx на роутере или постоянно работающем компьютере.
- Возможность направить DNS-запросы станции на этот сервер.
- [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools) с командой `adb`.
- [eQuasar](https://git.gay/iwakura/eQuasar): исходный вариант — commit `02f3c583a7d7335fc8f3f7d511ea795590b41341`.

Из eQuasar нужны конфигурация `copymetoroot/etc/nginx/sites-enabled/quasar`, сертификат `copymetoroot/opt/fakequasar/certs/fullchain.pem` и ключ `copymetoroot/opt/fakequasar/certs/quasar-all.key`. Пути установки зависят от системы. Используйте эту пару: доверие станции к другим сертификатам в рамках проверки не устанавливалось.

В командах `IP_СТАНЦИИ` замените адресом своей станции, `IP_DNS` — адресом DNS-сервера, `IP_NGINX` — адресом Nginx. Адрес станции можно найти в списке клиентов или DHCP роутера. Закрепите адреса станции и серверов, чтобы они не менялись при перезагрузке. Версию прошивки до ADB можно посмотреть в приложении, если она там отображается.

Подключите станцию к сети и аккаунту через приложение. Если она показывает требование оплатить подписку, настройка ниже выполняется после появления этого экрана.

## 1. Настроить DNS

Для станции направьте следующие имена на IP-адрес Nginx:

```text
quasar.yandex.net
quasar.yandex.ru
scbh.yandex.net
```

DNS должен быть доступен станции по **UDP и TCP 53**, Nginx — по **TCP 80 и 443**. Службы могут слушать другие порты, если роутер перенаправляет на них соответствующий трафик станции. Остальной HTTPS-трафик перенаправлять в Nginx не нужно.

Изменения DNS ограничьте станцией. Для остальных имён используйте обычный upstream DNS. Проверьте фактические запросы станции и ответы **A и AAAA**: IPv6, запасной DNS или шифрованный DNS могут направить запросы мимо подмены. В dnsmasq локальные зоны `local=/имя/` предотвращают отправку остальных типов запросов для подменяемых имён наружу. При отсутствии рабочего IPv6 для DNS станции можно использовать `filter-AAAA`; отключать IPv6 для всей сети не требуется.

Пример проверки DNS с сервера или другого разрешённого клиента:

```text
nslookup -type=A quasar.yandex.net IP_DNS
nslookup -type=AAAA quasar.yandex.net IP_DNS
nslookup -type=A updater.mobile.yandex.net IP_DNS
```

Для первого запроса ожидается `IP_NGINX`; реальный AAAA-адрес подменяемого имени не должен вести мимо Nginx. Для updater ожидается loopback после настройки раздела 3. Аналогично проверьте остальные имена. Эти запросы подтверждают ответ DNS-сервера для проверяющего клиента, но не то, какой DNS фактически использует станция.

Не включайте Private DNS в ходе настройки. После получения ADB его состояние можно проверить:

```bash
adb -s IP_СТАНЦИИ:5555 shell settings get global private_dns_mode
```

В проверенной конфигурации значение — `off`. Настройка обычного DNS не гарантирует перехват DoT/DoQ на порту 853 или DoH на порту 443.

Для работы Алисы и Кинопоиска оставьте обычный DNS для этих имён:

```text
rpc.alice.yandex.net
uniproxy.alice.yandex.net
alice.yandex.net
alice-ats.yandex.net
alice-ats-test.yandex.net
strm.yandex.ru
```

Не направляйте их на loopback. В частности, блокировка `strm.yandex.ru` мешает воспроизведению видео.

## 2. Настроить Nginx

Для `/get_sync_info` используйте следующий JSON:

```json
{
  "status": "ok",
  "config": {
    "account_config": {"spotter": "alisa"},
    "device_config": {"name": "quasar"},
    "system_config": {
      "adbd": {"remoteActivation": true, "network": true},
      "com.yandex.tv.services.platform": {
        "adbEnabled": true,
        "developmentSettingsEnabled": true
      }
    }
  },
  "subscription": {"mode": "transaction"}
}
```

Не заменяйте его сохранённым полным ответом настоящего сервера: старое состояние подписки в нём может выключить ADB. Форматирование JSON не меняет его смысл. Для побайтовой сверки компактная запись в указанном порядке, без пробелов и завершающего перевода строки, занимает **289 байт**, SHA256:

```text
f8b3ab73d96cc0c646a0d4345db483316b3affadee10a02dd06b5b7d3c20f0f7
```

В исходном описании проверки указано, что на 0921 этот ответ включал ADB после предварительного отключения отладки. Отдельный журнал этой проверки не найден. Короткий ответ исходного eQuasar отдельно в одинаковых условиях не проверялся.

Для трёх имён из раздела 1 настройте **HTTPS**:

| Путь | Код | Ответ |
|---|---:|---|
| `/generate_204` | 204 | Пустое тело |
| `/get_sync_info` | 200 | JSON выше |
| `/confirm_update` | 200 | `false` |
| `/check_updates` | 200 | `{"hasUpdate":false}` |
| `/allow_update` | 200 | `{"allow":false}` |
| Остальные пути, включая `/updates` и `/tv/api/v4/updates` | 403 | Отказ |

Обработчики должны работать с query-параметрами. Для JSON задайте `Content-Type: application/json`, для `/get_sync_info` также `Cache-Control: no-store`.

По **HTTP** `/generate_204` возвращает 204; остальные пути перенаправляются кодом 301 на HTTPS с сохранением имени, пути и query-параметров. В исходном eQuasar остальные HTTPS-запросы проксируются наружу — для этого варианта замените проксирование отказом 403. Ограничьте доступ к сервисам локальной сетью и нужными клиентами; посторонние Host не обслуживайте.

До перезагрузки проверьте конфигурацию `nginx -t` и ответ с сервера или разрешённого клиента. Пример для Linux/macOS:

```bash
curl -ki --resolve quasar.yandex.net:443:IP_NGINX https://quasar.yandex.net/get_sync_info
```

Ожидается HTTP 200 и JSON из раздела 2. Повторите проверку для остальных имён и ответов таблицы. Ключ `-k` отключает проверку доверия сертификату на компьютере: результат проверяет выдачу сервера, но не доказывает, что TLS примет станция. Если доступ к серверу разрешён только станции, проводите локальную проверку с самого сервера или отдельно разрешённого клиента. При нестандартном порту Nginx сначала проверьте его непосредственно, затем отдельно — перенаправление трафика станции.

Ограничение: отказ на `/push_subscribe` может нарушить функции приложения, в том числе эквалайзер. Фиксированный `/get_sync_info` также не передаёт новые настройки из облака.

## 3. Ограничить обновления

На DNS-сервере станции заблокируйте эти зоны и их поддомены:

```text
updater.mobile.yandex.net
quasar.s3.yandex.net
```

Для A-запросов можно вернуть `127.0.0.1`, для AAAA — `::1` или пустой ответ при `filter-AAAA`. Другие типы запросов этих зон не отправляйте upstream. В dnsmasq используются `address=/имя/127.0.0.1`, `address=/имя/::1` и `local=/имя/`. Это стандартные loopback-адреса станции.

Блокируйте `quasar.s3.yandex.net`, а не весь `s3.yandex.net`. Ограничение хоста затрагивает и другие ресурсы, включая модели распознавания. Ответы Nginx для обновлений заданы в разделе 2.

Это сетевая защита, а не полное отключение updater: другие адреса, кэшированные IP и уже скачанные обновления могут оставаться доступными. Не применяйте к Максу скрипты отключения OTA от Linux-станций и не отключайте updater вслепую.

## 4. Проверить ADB

1. Проверьте конфигурацию Nginx, DNS и ответы из таблицы; оставьте службы работающими. Для диагностики включите локальный журнал запросов с источником, именем хоста, путём и HTTP-кодом, без query-параметров и заголовков авторизации.
2. Перезагрузите станцию и дождитесь загрузки. В журнале Nginx убедитесь, что **станция** получила `/get_sync_info` с кодом 200; проверьте, что сервер выдаёт JSON из раздела 2. Запрос `/generate_204` сам по себе этого не подтверждает.
3. Подключитесь, подставив адрес станции:

   ```bash
   adb connect IP_СТАНЦИИ:5555
   adb -s IP_СТАНЦИИ:5555 shell id
   ```

4. Ожидается `uid=2000(shell)`; после него могут идти группы и SELinux-контекст. Повторите `shell id` через несколько минут после загрузки.
5. Если станция получила нужный ответ, но ADB не появился, перезагрузите её ещё раз: она может сначала применить ранее сохранённый конфиг. Если после второй загрузки результата нет, переходите к диагностике.

Если ADB появился после первой загрузки, вторая перезагрузка для его получения не нужна.

Если команда `adb` не найдена, проверьте установку Platform Tools и `PATH`. В Windows PowerShell из папки `platform-tools` используйте `./adb.exe` вместо `adb` в этих командах.

Версию можно проверить после подключения:

```bash
adb -s IP_СТАНЦИИ:5555 shell getprop ro.product.model
adb -s IP_СТАНЦИИ:5555 shell getprop ro.build.display.id
adb -s IP_СТАНЦИИ:5555 shell getprop ro.build.version.incremental
```

Отдельно проверьте голосовой запрос Алисе, музыку и нужное видео: работа ADB не подтверждает работу сервисов.

## Если не получилось

- **Станции нет в логах:** проверьте её адрес в роутере, доступность DNS и Nginx со стороны станции, firewall и изоляцию клиентов Wi-Fi/гостевой сети. Проверьте VPN или прокси на компьютере. Ответ DNS на компьютере ещё не доказывает, что станция использует тот же DNS.
- **Сервер не запускается или порты недоступны:** проверьте `nginx -t`, какие службы заняли порты 53/80/443, адреса прослушивания и firewall. Если используется перенаправление на другие порты, проверьте его отдельно.
- **Ошибка сертификата или `unknown_ca`:** проверьте цепочку и ключ из указанной версии eQuasar, имя сервера и прошивку. Успешный `curl -k` с компьютера не подтверждает, что сертификат принимает станция. Если станция по-прежнему отклоняет цепочку, совместимость с этой прошивкой не подтверждена; сброс или замена системных сертификатов не являются проверенным решением этого гайда.
- **Есть запрос, но ADB нет:** проверьте, что запрос `/get_sync_info` от станции получил HTTP 200 с указанным JSON и четырьмя флагами. Затем проверьте версию, маршрутизацию и доступность TCP 5555. `Connection refused` обычно означает отказ соединения, а таймаут может указывать на сетевой маршрут или firewall; ни один симптом сам по себе не устанавливает причину. После второй загрузки диагностируйте проблему вместо повторных перезагрузок.
- **ADB показывает `unauthorized` или `offline`:** проверьте `adb devices -l`, выбранный адрес и состояние транспорта.
- **ADB пропадает:** проверьте доступность подмены и значение `transaction` в выдаваемом ответе.
- **После отключения подмены пропал ADB или появился экран подписки:** восстановите DNS и Nginx, проверьте ответ станции и при необходимости перезагрузите её. Восстановление для любого состояния не гарантируется.
- **Алиса или видео не работают:** проверьте DNS имён из раздела 1 и логи соответствующих запросов; учтите ограничения 403 из раздела 2.

При запросе помощи уберите из логов адреса сети, токены, ключи, серийный номер, MAC-адреса, идентификаторы и личные пути. Укажите модель, прошивку, выполненные действия и последний подтверждённый этап.

## Для агента

Перед настройкой выясни модель и прошивку станции, ОС, модель роутера, адреса станции и серверов, текущий DNS-маршрут и доступные способы администрирования. Адаптируй службы и сетевые правила к этой сети, сохрани возможность отката и проверь каждый этап по инструкции. Сброс, перепрошивка, установка root и открытие доступа из интернета в задачу не входят.
